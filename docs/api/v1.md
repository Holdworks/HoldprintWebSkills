# API /v1

A API `/v1` é o contrato estável que plugins, funções, apps externos e a CLI usam para ler e escrever na conta. Nenhuma outra rota do Holdprint é acessível a um plugin.

## Endereço e autenticação

As rotas aparecem nesta página como `/v1/...`. Cada cliente chega nelas por um caminho:

| Quem chama | Como | Endereço | Credencial |
|---|---|---|---|
| Tela do plugin | `hold.api` do SDK | `/_hold/v1/...` na própria origem do plugin | Token do quadro, do usuário que abriu a tela, curto (cerca de 10 min) e renovado sozinho pelo SDK. Nunca aparece no seu código. |
| Função do plugin | `hold.api` de `createHold` | Endereço interno da hospedagem | Token da **instalação** (5 min), posto pela hospedagem; vale para agenda, evento, hook e "Executar agora". Na chamada vinda da tela, vale o token do usuário. |
| App externo (TV, celular) | `app.api` do `HoldprintExternal` | `https://api.{DOMINIO_TECNICO}/v1/...` | OAuth do Hold Identity (código de dispositivo ou redirecionamento com PKCE), acesso de 10 min renovado pelo SDK, sessão de até 90 dias. Só a partir da origem registrada. |
| CLI `holdprint` ou seu script no terminal | `holdprint api`, `holdprint query` | `{BASE_URL}/api/v1/...` | Hold Identity, código de dispositivo, cliente `holdprint-cli`. Acesso de 1 hora, renovação por até 30 dias. Cabeçalho `Authorization: Bearer <token>`. |

### Hold Identity (OAuth)

O Hold Identity é o servidor de autorização do Holdprint para tudo que não é a tela do ERP. A pessoa sempre aprova **dentro do Holdprint**, já logada; nenhum desses clientes vê a senha.

| Rota | Para quê |
|---|---|
| `GET {BASE_URL}/api/v1/platform/identity/.well-known/oauth-authorization-server` | Descoberta (endpoints, escopos suportados). |
| `POST {BASE_URL}/api/v1/platform/identity/device/code` | Inicia o código de dispositivo (`client_id`, `scope` opcional). Devolve `device_code`, `user_code`, `verification_uri`, `verification_uri_complete`, `interval`, `expires_in`. |
| `POST {BASE_URL}/api/v1/platform/identity/token` | Troca o código (`grant_type=urn:ietf:params:oauth:grant-type:device_code`) ou renova (`refresh_token`). Respostas de espera: `authorization_pending`, `slow_down`; fim: `access_denied`, `expired_token`. |
| `POST {BASE_URL}/api/v1/platform/identity/revoke` | Revoga o token (logout). |
| `GET {BASE_URL}/api/v1/platform/identity/jwks` | Chaves públicas para conferir tokens e contextos assinados. |

- Cada renovação troca o refresh token; reaproveitar um refresh antigo derruba a sessão inteira (proteção contra roubo).
- A pessoa vê e desconecta cada acesso em **Plugins > Acessos conectados**. Desconectar corta o acesso na próxima renovação.
- Hoje os clientes do Hold Identity são a CLI, o MCP do Holdprint e os apps externos declarados por plugins. Não há cadastro de cliente OAuth avulso.

### O plugin vê o que o usuário vê

- O token só carrega os escopos aprovados que o perfil de quem abriu a tela pode usar. Ex.: `budgets:read`, `funnels:read` e `tasks:*` exigem acesso ao painel de Negociações; `customers:read`, à tela de Clientes; `jobs:read`, à tela de Jobs. Sem a permissão de tela: `403 HOLD_PLUGIN_PLATFORM_9`.
- As respostas seguem a regra da tela: sem "ver negociações de outros vendedores", `/budgets` devolve só os orçamentos do próprio vendedor e `/tasks` só as tarefas desses orçamentos; `/customers` aplica a carteira do perfil.
- Token de instalação (funções sem usuário) enxerga a conta inteira, dentro dos escopos aprovados.

### Contrato máquina-legível

`GET {BASE_URL}/anonymous-api/plugin-platform/openapi/v1.json` (sem token). Cada operação traz `x-hold-scopes` (escopos exigidos) e, nas escritas, `x-hold-idempotent`.

## Rotas

| Rota | Escopo | O que faz |
|---|---|---|
| `GET /v1/me` | nenhum | Usuário e conta do token. Com token de instalação: `{ principal: "installation", installationId, pluginId, accountId, accountName, trigger, scopes }`. |
| `GET /v1/budgets` | `budgets:read` | Orçamentos (página ou cursor). |
| `GET /v1/budgets/{id}` | `budgets:read` | Um orçamento. |
| `PUT /v1/budgets/{id}/step` | `budgets:move-step` | Move o orçamento de etapa no funil. |
| `GET /v1/customers` | `customers:read` | Clientes (página ou cursor). |
| `GET /v1/funnels`, `GET /v1/funnels/{id}` | `funnels:read` | Funis e etapas. |
| `GET /v1/users` | `users:read` | Usuários ativos. |
| `GET /v1/tasks` | `tasks:read` | Tarefas de orçamento (página ou cursor). |
| `POST /v1/tasks` | `tasks:write` | Cria tarefa (use `Idempotency-Key`). |
| `PUT /v1/tasks/{id}/complete` | `tasks:write` | Conclui a tarefa. |
| `GET /v1/query` | nenhum | Catálogo da consulta genérica (recursos, campos, filtros, ordenações). |
| `GET /v1/{recurso}/{id}` | `<recurso>:read` | Um registro de qualquer recurso do catálogo. |
| `POST /v1/{recurso}/query` | `<recurso>:read` | Consulta genérica com filtro, campos, ordenação e cursor. |
| `GET /v1/events` | o do tipo de evento | Feed de eventos. |
| `GET/PUT/DELETE /v1/storage/...` | implícito | Dados do plugin (use `hold.storage`). |
| `GET /v1/actions`, `GET /v1/actions/{chave}` | sessão da CLI ou do MCP | Catálogo de ações de escrita. |
| `POST /v1/actions/approvals`, `GET /v1/actions/approvals/{id}` | sessão da CLI ou do MCP | Pedido e andamento de aprovação (caso raro). |

`storage` e `events` exigem uma instalação de plugin (não funcionam com a sessão da CLI). `actions` exige a sessão da CLI ou do MCP (não funciona com o token de plugin).

## Paginação

### Modo página (`page`/`pageSize`)

`page` (a partir de 1, padrão 1) e `pageSize` (padrão 20, **máximo 100**).

```json
{ "data": [ ... ], "totalCount": 33, "page": 1, "pageSize": 25, "totalPages": 2, "hasNextPage": true, "hasPreviousPage": false }
```

`GET /v1/funnels` devolve `{ "data": [...] }` sem campos de página.

### Modo cursor e sincronização (`/budgets`, `/customers`, `/tasks`)

Entra em modo cursor quando a query traz `cursor`, `updated_since` ou `limit`.

```text
GET /v1/budgets?updated_since=2026-11-13T12:00:00Z&limit=100[&cursor=<opaco>][&state=open]
```

```json
{ "data": [{ "id": "...", "updatedAt": "...", "deleted": false }], "nextCursor": "...", "hasMore": true, "syncToken": "2026-11-13T12:04:55Z" }
```

- `limit` até 100. Siga `nextCursor` enquanto `hasMore`. O cursor é opaco e vale só para o mesmo recurso.
- `updated_since` (ISO 8601) traz só o que mudou depois dele, **incluindo os excluídos com `deleted: true`**.
- Guarde `syncToken` (início da consulta menos 5 s) como o próximo `updated_since` e tire duplicados por `id`. É o que `hold.sync.pull` faz por você.
- Só escritas feitas pelo Holdprint carimbam a alteração; mudanças feitas por fora podem não aparecer.

## Orçamentos

`GET /v1/budgets`: `state` (`open`, `won` ou `lost`), `sellerId`, `customerId`, `code`, `startDate`, `endDate` (filtram pela criação), `page`, `pageSize`.
- Sem `startDate` nem `endDate`, vale a criação nos **últimos 90 dias** (só no modo página).
- `updated_before=<ISO>` com `state=Open` traz os orçamentos sem movimento desde a data (bom para follow-up).
- Use `pageSize=25` e desenhe a tela conforme as páginas chegam.

Item:

```text
{ id, customerId, code, title, customerName, budgetState (1 aberto, 2 perdido, 3 ganho), creationDate,
  deliveryNeed, wonDate, lostDate ("0001-01-01T00:00:00Z" = vazio), sellerId, sellerName,
  proposes: [{ paymentOption, totalPrice, totalProfitPercentual, productionCost, sellingCost, proposeItems (sempre []), isWinner }] }
```

O valor do orçamento é o `totalPrice` da proposta com `isWinner` (ou o maior `totalPrice` se nenhuma ganhou).

### Mover etapa: `PUT /v1/budgets/{id}/step`

Corpo `{ "stepId": "<id da etapa do funil do orçamento>" }`, com `Idempotency-Key`. Devolve o orçamento com `funnelId`, `stepId`, `stepName`. A etapa muda como na tela e cria a tarefa "Mudança de etapa", com a autoria "por <usuário> via plugin <nome>". Erros: `404 _30` orçamento inexistente ou invisível; `400 _44` etapa fora do funil; `400 _45` orçamento não está aberto.

## Clientes, funis e usuários

- `GET /v1/customers`: `searchTerm`, `page`, `pageSize`. Item: `{ id, name, fullName, mainEmail, mainPhoneNumber, document, site, entityType, active, creationTime, lastUpdateTime, salesCreditLimit, avaibleSalesCreditLimit, salesCreditLimitExpirationDate, isCreatedFromLead, leadCreationTime, leadConvertionTime, addresses[], contacts[{ name, email, phoneNumber, position }], customFields[] }`.
- `GET /v1/funnels?type=budget`: `{ id, name, type, steps: [{ id, name, type, successProbability }] }`.
- `GET /v1/users?searchTerm=`: `{ id, name, email, profileId }` (só ativos e não bloqueados).

## Tarefas

`GET /v1/tasks`: `budgetId`, `responsibleUserId`, `status` (`pending` ou `done`; omitido = todas), `page`, `pageSize`. Item: `{ id, budgetId, title, taskType, taskTypeName, description, schedulingTime, duration, responsibleUserId, entityId, visibleForCustomer, isDone, endTime, completedByUserId, creationTime }`.

`taskType`: 1 Ligação, 2 Reunião, 3 Tarefa, 4 Prazo, 5 Envio de e-mail, 6 Almoço, 7 Visita, 8 Envio de proposta, 9 Anotação.

`POST /v1/tasks`:

```json
{ "budgetId": "...", "title": "Follow-up", "taskType": 3, "schedulingTime": "2026-11-13T12:00:00.000Z",
  "duration": 0, "description": "...", "responsibleUserId": "...", "visibleForCustomer": false }
```

- Obrigatórios: `budgetId` e `title`. Padrões: `taskType` 3, `schedulingTime` agora, `responsibleUserId` o usuário do token (na função sem usuário, o vendedor do orçamento).
- `201` cria; **`200` com a mesma tarefa** ao repetir a mesma chave e o mesmo corpo; `400 HOLD_GENERAL_6` ao repetir a chave com corpo diferente; `404 _30` orçamento inexistente ou invisível.

`PUT /v1/tasks/{id}/complete`: `200` com `isDone: true`. Repetir é seguro.

## Consulta genérica

`GET /v1/query` devolve o catálogo atual. Leia uma vez em vez de adivinhar.

`POST /v1/{recurso}/query`:

```json
{
  "where": { "deleted": { "eq": false }, "isFinalized": { "eq": false }, "deliveryNeeded": { "lte": "2026-11-20T00:00:00Z" } },
  "fields": ["id", "code", "title", "customerId", "deliveryNeeded", "totalPrice"],
  "sort": "deliveryNeeded",
  "limit": 100,
  "cursor": null,
  "updatedSince": null
}
```

Resposta: `{ "data": [...], "nextCursor": "..." }`. Repita com `cursor` enquanto `nextCursor` não for `null`.

- Operadores: `eq`, `in` (lista), `gte`, `lte`.
- `sort`: um campo da lista do recurso; prefixo `-` para decrescente.
- `limit`: padrão 50, máximo 100.
- `updatedSince`: só nos recursos marcados abaixo.
- Filtro só em campo indexado (`400 _94`, com a lista dos permitidos); campo fora da lista (`400 _95`); recurso desligado (`404 _93`).

## Eventos

`GET /v1/events?cursor=<opaco|now>&types=budget.won,task.created&limit=100` → `{ data: [evento], nextCursor, hasMore }`. Sem `cursor`, começa em "agora".

```json
{ "type": "budget.won", "timestamp": "2026-11-13T14:02:11Z",
  "data": { "id": "evt_8f3c...", "accountId": 1234, "budgetId": "6a62...", "budgetCode": 1234,
            "actor": { "type": "user", "id": "...", "name": "Fulano", "viaPluginId": null } } }
```

| Evento | Escopo | Campos extras em `data` |
|---|---|---|
| `budget.won` | `budgets:read` | |
| `budget.step_changed` | `budgets:read` | `fromStepId`, `toStepId` |
| `task.created`, `task.completed` | `tasks:read` | `taskId`, `budgetId` |
| `customer.created` | `customers:read` | `customerId`, `source` (`screen`, `lead`, `import`, `api`) |

- Entrega ao menos uma vez e sem ordem: deduplique por `data.id`. O evento só traz identificadores; leia o dado pela API.
- Filtra pelos escopos e pela visibilidade do usuário. Fica fora da cota diária (conta no limite por minuto).
- Cursor inválido: `400 _53` (recomece com `cursor=now`); cursor com mais de 30 dias: `410 _54` (releia por sincronização).

**Webhook** (opcional, `events.webhook.url` no manifesto): o mesmo corpo, por POST, assinado no padrão Standard Webhooks: cabeçalhos `webhook-id` (igual ao `data.id`), `webhook-timestamp` e `webhook-signature: v1,<HMAC-SHA256 em base64>` sobre `id.timestamp.corpo`, com o segredo `whsec_...` (`holdprint plugin webhook-secret`). Confira a assinatura, recuse timestamp velho e deduplique por `webhook-id`. Responda 2xx rápido; falhas são repetidas (5 s, 5 min, 30 min, 2 h, 5 h, 10 h, 14 h, 24 h, por cerca de 3 dias) e o Administrador pode reenviar em **Plugins > ⋯ > Chamadas e cotas > Avisos enviados**.

## Storage

Escopo implícito, isolado por plugin e por conta, **compartilhado entre os usuários da conta** (não guarde dado do ERP).

| Rota | Resposta |
|---|---|
| `GET /v1/storage/{colecao}?prefix=&cursor=&limit=` (limit 1 a 100) | `{ items: [{ collection, key, value, sizeBytes, updatedAt }], nextCursor }`, por `key` |
| `GET /v1/storage/{colecao}/{chave}` | O **registro** `{ collection, key, value, sizeBytes, updatedAt }` (o valor está em `value`), ou 404 |
| `PUT /v1/storage/{colecao}/{chave}` | Corpo = o próprio valor (sem embrulho). Cria ou substitui. |
| `DELETE /v1/storage/{colecao}/{chave}` | 204 (idempotente) |

`colecao`: `^[a-z0-9][a-z0-9_-]{0,63}$`; `chave`: `^[A-Za-z0-9][A-Za-z0-9._:-]{0,127}$`. Até 256 KiB por valor e 5 mil registros por plugin. Prefira `hold.storage`, que devolve só o valor.

## Ações de escrita

Além das escritas do `/v1` (tarefas, etapa), a sessão da **CLI** (e o MCP) pode executar as rotas de escrita do Holdprint que a plataforma expõe: cadastrar cliente, criar e ganhar orçamento, lançar e baixar conta, movimentar estoque, preço de insumo, anexar arquivo e muitas outras. Plugins não usam este caminho.

1. **Listar:** `GET /v1/actions?search=<texto>&risk=low|medium|high` (CLI: `holdprint actions list`). Cada item: `key` (ex.: `CustomersController.Create:POST:api/customers`), `label`, `method`, `route`, `scope`, `risk`, `impact`, `reviewed`, `idempotency`, `permission`.
2. **Descrever:** `GET /v1/actions/{key}` (CLI: `holdprint actions describe <key>`): a ação e o JSON Schema do corpo.
3. **Prévia:** `holdprint actions run <key> --data @corpo.json --dry-run` mostra método, caminho final, corpo, risco, impacto e a `Idempotency-Key` **sem enviar**. Use antes de dinheiro, nota fiscal ou mensagem externa.
4. **Rodar:** a CLI chama a própria rota da ação, com o token da sessão e `Idempotency-Key`.

Regras:
- **`Idempotency-Key` obrigatória** em toda escrita pela sessão da CLI (sem ela, `400 _90`). A CLI calcula a chave do conteúdo (método, rota e corpo). Janela de **24 horas**: dentro dela, a mesma escrita vira uma só e a resposta guardada volta com `Idempotent-Replayed: true`. Mesma chave com corpo diferente: `400`.
- **Escritas simultâneas:** até 4 por conta; acima disso, `429 _96` com `Retry-After`. Repita com a mesma chave.
- **Aprovação (caso raro):** nenhuma rota pede aprovação por padrão. Se a plataforma marcar uma, a chamada responde `428 _89`. Peça com `POST /v1/actions/approvals` `{ method, path, body }`, abra a URL devolvida (`{APP_URL}/aprovacoes/<id>`, um Administrador aprova), acompanhe em `GET /v1/actions/approvals/{id}` (`pending`, `approved`, `rejected`, `expired`, `consumed`) e repita a **mesma** chamada com o cabeçalho `x-hold-approval: <approvalId>`. A aprovação vale uma execução, por 30 minutos, para exatamente aquele corpo (`409 _91` se mudar). Há um teto diário de aprovações por conta (`429 _92`).
- Rota fora do catálogo de ações: `403 _88`. Rota que não aceita a sessão da CLI: `403 _85`.
- O Administrador pode desligar o acesso por CLI e MCP da conta inteira (tela Plugins); aí todas as chamadas da sessão da CLI respondem 403.

## Cotas e limites

| Limite | Valor |
|---|---|
| Chamadas por instalação de plugin | 10 mil por dia e 300 por minuto (o Administrador pode definir menos). Acima: `429` com `Retry-After` (`_39` diária, `_40` por minuto). |
| Feed de eventos | Fora da cota diária; conta nos 300 por minuto. |
| Página | Até 100 itens (`pageSize`, `limit`). |
| Consulta | Até 5 s; acima: `503 _43` (reduza o intervalo ou o `limit`). |
| Função | 50 chamadas à API e 35 s por execução. |
| Storage | 256 KiB por registro, 5 mil registros por plugin. |
| Hook | Corpo até 256 KiB. |
| Escritas simultâneas pela CLI | 4 por conta. |

A cota limita só o plugin, nunca o Holdprint. O consumo aparece em **Plugins > Chamadas e cotas**, atualizado a cada minuto.

## Formato de erro

```json
[{ "type": 59, "errorType": 9, "errorCode": "HOLD_PLUGIN_PLATFORM_9", "fields": ["budgets:read"], "message": "..." }]
```

`fields` aponta o campo ou o escopo; quando existe, `message` traz a explicação em português. Tabela completa em [Erros](https://docs.holdworks.ai/plugins/erros.md).
