Contas a Pagar

Consulta, criação, edição e baixa de despesas, com classificação no plano de contas e centros de custo.

Endpoints

  • GET/api-key/expenses/data
  • POST/api-key/expenses
  • PATCH/api-key/expenses/{id}
  • POST/api-key/expenses/{id}/settle

GET/api-key/expenses/data#

Consulta despesas de forma paginada, com suporte a filtros por data, status, fornecedor e categoria. Os dados incluem informações contábeis, centros de custo e detalhes de pagamento, facilitando relatórios financeiros e controle de custos. Requer autenticação via API Key no header x-api-key.

Filtro Padrão

Se nenhuma data for informada, este endpoint retorna apenas despesas do mês corrente. Para consultar despesas de outros períodos, sempre especifique as datas.

Parâmetros de Query#

CampoTipoObrigatórioDescrição
pageintopcionalNúmero da página para paginação (padrão: 1)
limitintopcionalQuantidade de registros por página (padrão: 50 • máximo: 100)
start_datestringopcionalData inicial para filtro (formato: YYYY-MM-DD). Exemplo: 2025-01-01
end_datestringopcionalData final para filtro (formato: YYYY-MM-DD). Exemplo: 2025-12-31
translatebooleanopcionalTraduzir nomes de campos (true/false). Padrão: false
statusstringopcionalFiltrar por status (pending, paid, overdue, cancelled). Exemplo: paid
supplier_idintopcionalFiltrar despesas de um fornecedor específico. Exemplo: 55
categorystringopcionalFiltrar por categoria de despesa. Exemplo: equipment_rental

Status das Despesas#

CampoTipoDescrição
pendingstringPendente - Despesa aguardando pagamento
paidstringPaga - Despesa quitada
overduestringVencida - Despesa não paga após o vencimento
cancelledstringCancelada - Despesa cancelada

Categorias de Despesas#

CampoTipoDescrição
paper_suppliesstringPapel e substratos
ink_suppliesstringTintas e consumíveis de impressão
equipment_rentalstringAluguel de equipamentos
equipment_maintenancestringManutenção de equipamentos
utilitiesstringUtilidades (luz, água, internet)
laborstringMão de obra
servicesstringServiços terceirizados
otherstringOutras despesas

Centros de Custo#

CampoTipoDescrição
productionstringCustos diretos de produção
administrationstringCustos administrativos
salesstringCustos comerciais e vendas
logisticsstringCustos de logística e entrega

Dica

Use os filtros de category e cost_center para gerar relatórios específicos por tipo de despesa ou área da empresa.

Estrutura de Dados#

CampoTipoDescrição
idnumberIdentificador único da despesa
descriptionstringDescrição da despesa
amountnumberValor da despesa
due_datestringData de vencimento (YYYY-MM-DD)
payment_datestring | nullData do pagamento (YYYY-MM-DD)
statusstringStatus da despesa (pending, paid, overdue, cancelled)
supplierobjectInformações do fornecedor
categorystringCategoria da despesa
cost_centerstringCentro de custo contábil
payment_methodstring | nullMétodo de pagamento utilizado
invoice_numberstringNúmero da nota fiscal

Boas Práticas

  • Sempre especifique datas para evitar dados incompletos
  • Use paginação para grandes volumes de dados
  • Monitore despesas vencidas (status: overdue) regularmente
  • Filtre por centro de custo para análises departamentais

POST/api-key/expenses#

Cria uma conta a pagar, à vista ou parcelada. A conta nasce em aberto; para registrar o pagamento, use /api-key/expenses/{id}/settle. A criação aparece no histórico da conta como feita pela integração (API).

Autenticação via API Key no header x-api-key e Content-Type: application/json.

Headers#

CampoTipoObrigatórioDescrição
Idempotency-KeystringRecomendadoIdentificador único da operação no seu sistema (até 200 caracteres). Reenviar a mesma chave com o mesmo corpo devolve a conta já criada, sem duplicar. A mesma chave com corpo diferente é recusada

Request Body#

CampoTipoObrigatórioDescrição
descriptionstringobrigatórioDescrição da conta a pagar
amountnumberobrigatórioValor total. Maior que zero
dueDatestringobrigatórioVencimento (ISO 8601, ex.: 2026-11-10). No parcelamento, é a data base das parcelas
chartOfAccountsarrayobrigatórioClassificação no plano de contas: lista de { publicId, amount }. Com um único item, amount pode ser omitido (usa o valor total). Com mais de um, cada item precisa de amount e a soma deve ser igual a amount
paymentMethodIdstringobrigatórioForma de pagamento (/api-key/payment-methods/data). Obrigatório quando não houver paymentOptionId
paymentOptionIdstringobrigatórioCondição de pagamento (/api-key/payment-options/data, com uso em compra). Informe para parcelar; as parcelas seguem a condição
installmentsarrayopcionalParcelas personalizadas: lista de { dueDate, amount }. Exige paymentOptionId; a soma deve ser igual a amount
supplierIdstringopcionalId do fornecedor (/api-key/suppliers/data)
companyIdstringopcionalId da empresa emissora, em contas com mais de um CNPJ. Se omitido, usa a empresa padrão da conta
documentNumberstringopcionalNúmero do documento (nota, boleto, contrato)
notesstringopcionalObservações

À vista ou parcelado

Sem paymentOptionId, é criada uma única conta com a forma de pagamento informada. Com paymentOptionId, é criada uma conta por parcela, conforme a condição de pagamento ou a lista installments. A resposta traz todas as parcelas em items.

PATCH/api-key/expenses/{id}#

Altera uma conta a pagar em aberto. Envie só os campos que mudam; os demais ficam como estão. A alteração aparece no histórico da conta.

Só é aceita para conta sem pagamento registrado. Conta paga ou com pagamento parcial devolve 400; id inexistente ou de outra conta devolve 404.

Request Body#

CampoTipoObrigatórioDescrição
descriptionstringopcionalNova descrição
amountnumberopcionalNovo valor. Se a conta tiver mais de uma classificação no plano de contas, envie também chartOfAccounts
dueDatestringopcionalNovo vencimento (ISO 8601)
documentNumberstringopcionalNúmero do documento
notesstringopcionalObservações
chartOfAccountsarrayopcionalNova classificação: lista de { publicId, amount }, com as mesmas regras da criação

Resposta 200: { "success": true, "data": { ...conta a pagar atualizada... } }, no mesmo formato de cada item da criação.

POST/api-key/expenses/{id}/settle#

Registra o pagamento (pagamento) de uma conta a pagar, com o mesmo efeito da baixa feita pela tela: a conta muda de status e a movimentação entra no extrato da conta financeira.

Headers#

CampoTipoObrigatórioDescrição
Idempotency-KeystringRecomendadoIdentificador único do pagamento no seu sistema. Se a resposta se perder e você reenviar a mesma baixa com a mesma chave, o pagamento não é lançado de novo

Request Body#

CampoTipoObrigatórioDescrição
financialAccountIdstringobrigatórioConta financeira (banco ou caixa) da movimentação. Consulte em /api-key/financial-accounts/data
paymentMethodIdstringobrigatórioForma de pagamento (/api-key/payment-methods/data)
datestringobrigatórioData do pagamento (ISO 8601)
amountnumberobrigatórioValor efetivamente pago, já com juros e multa somados e desconto abatido
interestAmountnumberopcionalJuros
fineAmountnumberopcionalMulta
discountAmountnumberopcionalDesconto
partialbooleanopcionalUse true para pagamento parcial; o saldo continua em aberto

Conta do valor

Para quitar, amount + discountAmount − interestAmount − fineAmount deve ser igual ao saldo em aberto (openAmount). Exemplo: saldo 1.000,00, juros 20,00 e desconto 10,00 → amount = 1.010,00. Valores menores que o saldo só são aceitos com partial: true; valores maiores que o saldo são recusados.

Resposta 200 com a conta a pagar atualizada (status Paid, openAmount 0 e settlementDate preenchida). Conta já paga devolve 400.
